# 服务职责收敛方案

状态：原始设计草案，实施结果以 [互动域迁移与切换](interaction_migration.md) 为准。实现采用 Go 在事务内维护互动统计投影，未保留 Java 异步增减统计。目标是收敛写入职责与失败恢复路径，保留现有框架和已稳定的服务拆分。

## 现状与问题

当前点赞先由 interaction-rpc 写 Redis，再发布事件；Java InteractionEventListener 保存互动明细、更新帖子计数和 ES，并调用 notification-rpc。

- Redis 写成功、消息发送失败时仍返回成功；缓存过期后从 MongoDB 回填可能丢失已确认的互动。
- Java 同时承担互动持久化、帖子统计、搜索索引和通知编排。
- Java Listener 和 sync-sidecar 都写 ES，更新职责分散。
- 消费端唯一索引只能拦截重复明细，不能修复“明细成功、计数失败”的部分执行。
- 通知 Upsert 会刷新未读状态，不能直接当作事件投递幂等：同一事件重投不应再次恢复未读。

## 数据归属

| 服务 | 负责写入 | 说明 |
|---|---|---|
| platform-java | 帖子、关注、审核、帖子统计投影 | 保留已有内容业务，不回迁评论 |
| user-rpc | 账号、资料、认证状态 | 保留现状 |
| interaction-rpc | 点赞、收藏、评分、评论点赞明细 | MongoDB 为持久化依据，Redis 为可重建读模型 |
| comment-rpc | 评论、回复树及评论领域规则 | 保留现状；评论点赞明细归互动域 |
| notification-rpc | 通知、未读状态 | 先保留 Java RPC 编排，后续再迁事件消费 |
| sync-sidecar | Elasticsearch 索引 | 最终统一索引写入口 |
| search-rpc / gateway-api | 搜索查询 / 鉴权与聚合 | 不写互动事实数据 |

共享 MongoDB 实例不代表共享写入权限；迁移后同一集合只保留一个领域写入负责人。用户注销清理、后台操作也需检查。

## 第一阶段：只完成帖子点赞与取消点赞

涉及 Go likePostLogic.go、unlikePostLogic.go、common.go、ServiceContext，新建互动存储接口；涉及 Java InteractionEventListener 与既有 Mongo 索引。

1. 核对 PostLikeDoc 字段、集合名、联合唯一索引及所有写入调用，复用现有数据，不新建平行事实集合。
2. Go 同步执行 MongoDB 点赞插入/取消；重复插入、重复取消不产生新业务变化。数据库失败时返回失败。
3. 持久化成功后失效或更新 Redis；缓存失败不能撤销已提交的互动，读路径必须能回源恢复。需要专门验证并发回填与取消点赞交错，不能仅靠删除缓存宣称一致。
4. Java 不再写帖子点赞明细，只处理后续投影。生产者与消费者必须协调切换，避免新 Go 已写明细后被旧 Java 当成重复消息跳过。

### 可靠事件是本阶段的设计门槛

仅改成“MongoDB 后发 MQ”仍有双写缺口。正式实现前先检查本地/生产 Mongo 是否为副本集，以及是否支持所需事务。

- 若支持事务：互动状态与 Outbox 事件同事务提交；后台投递确认成功后标记完成，允许崩溃后重复投递，消费者按 eventId 幂等。
- 若为单机：不假定独立明细写入与 Outbox 插入具有原子性。需在副本集事务和单文档状态+待投递事件方案中选择并验证；该选择完成前不切换写入路径。
- 不将 MQ 发布返回 nil 等同于消费者已处理；投递需覆盖 Confirm、路由失败、重连、重试和未完成事件查询。

事件需明确 eventId、schemaVersion、目标与操作者、动作、发生时间；如允许乱序，另需状态版本/重算策略，不能依靠时间戳或计数增减自动收敛。

## 第二阶段：统计与 ES

- 保留 Java 对帖子统计的写入职责，但移除其互动明细写入和直接更新 ES 的路径。
- 不再无条件重放 +1/-1。先定义统计修复方式：由互动域提供聚合结果，Java 按目标串行重算，或采用有版本的统计快照。要验证重复、乱序和删除竞态。
- Java 完成帖子统计后产生索引刷新任务，由 sidecar 从当前帖子状态重建对应 ES 文档。
- 帖子更新与索引任务也存在双写边界，必须具有可重试任务或定期重建修复路径。
- 验证帖子编辑和互动更新并发时，不会用旧文档覆盖新统计；ES 暂时不可用不影响互动持久化。

## 第三阶段：推广与可选整理

点赞闭环稳定后，再逐项处理收藏、评分、评论点赞；评分单独覆盖改分、人数与均值计算，不机械套用点赞增减模型。

通知编排暂留 Java 调用 notification-rpc，避免同时迁移全部消费者。后续迁入通知域时，分清 eventId 去重与业务通知合并；旧事件重投不能把已读通知重新变成未读。

Redis 客户端统一、公共观测封装与框架迁移不纳入本轮。

## 验证与切换

- 单测：新点赞、重复点赞、取消不存在记录、数据库失败、缓存失败、事件持久化失败。
- 并发：同用户重复请求、点赞/取消交错、缓存回填与写入交错。
- 故障：提交后进程退出、MQ 断连、重复/乱序投递、ES 不可用、重启后任务恢复。
- 集成：历史互动可回填；通知只产生应有副作用；Mongo 统计与明细可核对；ES 能重建。
- 回归：现有 Go/Java 测试与五条 Smoke；更新当前“MQ 失败仍成功且只有 Redis 状态”的旧测试预期。
- 切换时暂停互动写请求并排空旧事件，完成消费者与生产者协调发布后恢复；单机练手环境采用维护窗口，不引入双写灰度机制。
- 回退需同时恢复兼容的生产者/消费者，并处理已提交明细和待投递事件；不能仅回滚二进制。

每阶段独立提交和验证。第一阶段尚未闭环时，不继续推广其余互动操作。
